# Подключение и запуск FlyArchOs в VirtualBox

Это подробная инструкция для первого запуска FlyArchOs в виртуальной машине:
как скачать ISO, подключить его к виртуальному оптическому приводу, создать
машину с нужными настройками, установить систему, отключить ISO после
установки и подключить сеть, SSH, общие папки и USB-устройства.

Термины:

- **хост** — компьютер и ОС, на которых запущен VirtualBox;
- **гость** — FlyArchOs внутри виртуальной машины;
- **VM/ВМ** — виртуальная машина VirtualBox.

> Для проверки конкретного бета-кандидата есть отдельный короткий чек-лист
> качества: [VIRTUALBOX-TEST.md](VIRTUALBOX-TEST.md). Общая последовательность
> установки из live-сессии описана в [INSTALL.md](INSTALL.md).

---

## 1. Требования к компьютеру

Минимально комфортно:

| Ресурс | Минимум | Рекомендуется |
|---|---:|---:|
| VirtualBox | 7.x | актуальный 7.x |
| Свободная RAM хоста | 8 ГБ | 16 ГБ и больше |
| RAM виртуальной машины | 6 ГБ | 12 ГБ |
| Процессоры ВМ | 2 | 4 |
| Виртуальный диск | 40 ГБ | 40–80 ГБ |
| Видеопамять | 128 МБ | 128 МБ |
| Архитектура хоста | x86_64 | x86_64 с включённой виртуализацией |

FlyArchOs собирается только для `x86_64`. На компьютере с ARM-процессором,
например Mac с Apple Silicon, VirtualBox не запустит этот ISO как обычную
x86_64-виртуальную машину.

В BIOS/UEFI хоста должна быть включена аппаратная виртуализация:

- Intel: **VT-x / Intel Virtualization Technology**;
- AMD: **SVM Mode / AMD-V**.

## 2. Скачайте ISO

### 2.1. Какой образ выбрать

Для первого подключения удобнее **mini**: он скачивается одним целым ISO.
**full** нужен, если хотите сразу проверить все дополнительные наборы ПО,
пресеты установщика и второе ядро.

Актуальные на момент написания бета-образы 1.7.0-beta:

#### Mini №58 — рекомендуется для первого запуска

- Страница релиза: <https://github.com/Nan6767/OsNan/releases/tag/iso-58-mini>
- Прямой ISO: <https://github.com/Nan6767/OsNan/releases/download/iso-58-mini/flyarchos-1.7.0-beta-x86_64.iso>
- Размер: `1 911 767 040` байт
- SHA-256:

```text
e1ed46fad5443bb1c6e5ce71943af2c568fe59e3432f82579b750b012797ae07
```

Mini №56 был первым образом, для которого CI доказал наличие Calamares;
№58 собран позже из `main` после слияния тех же исправлений и заменяет №56
для новых загрузок.

#### Full №57

- Страница релиза: <https://github.com/Nan6767/OsNan/releases/tag/iso-57-full>
- Один ZIP из артефакта сборки (прямая загрузка `.zip`):
  <https://nightly.link/Nan6767/OsNan/actions/runs/40792766889/flyarchos-full-iso-57.zip>
- Запасная ссылка на тот же артефакт:
  <https://nightly.link/Nan6767/OsNan/actions/artifacts/12864344250.zip>
- SHA-256 готового ISO:

```text
b64c3b13e9648465a510704a44c6d568c3ba1568be890418f1a8255be4347be7
```

ZIP нужно распаковать: VirtualBox подключает **сам файл `.iso`**, а не ZIP-архив.

Если ZIP недоступен, скачайте из релиза все части
`flyarchos-1.7.0-beta-x86_64.iso.part00` … `.part05` в одну папку и склейте их.

Windows, командная строка в папке с частями:

```bat
copy /b flyarchos-1.7.0-beta-x86_64.iso.part00+flyarchos-1.7.0-beta-x86_64.iso.part01+flyarchos-1.7.0-beta-x86_64.iso.part02+flyarchos-1.7.0-beta-x86_64.iso.part03+flyarchos-1.7.0-beta-x86_64.iso.part04+flyarchos-1.7.0-beta-x86_64.iso.part05 flyarchos-1.7.0-beta-x86_64.iso
```

Linux:

```bash
cat flyarchos-1.7.0-beta-x86_64.iso.part* > flyarchos-1.7.0-beta-x86_64.iso
```

### 2.2. Проверьте контрольную сумму

Проверка не обязательна для запуска, но сразу исключает повреждённую загрузку.

Windows PowerShell:

```powershell
Get-FileHash .\flyarchos-1.7.0-beta-x86_64.iso -Algorithm SHA256
```

Linux:

```bash
sha256sum flyarchos-1.7.0-beta-x86_64.iso
```

macOS:

```bash
shasum -a 256 flyarchos-1.7.0-beta-x86_64.iso
```

Результат должен совпасть с SHA-256 выбранного образа выше. Для более
поздних релизов сверяйтесь не с числами в этом файле, а с файлом
`*.iso.sha256` и описанием именно того релиза, который скачали.

## 3. Создайте виртуальную машину

Откройте VirtualBox и нажмите **Machine → New**
(в русском интерфейсе обычно **Машина → Создать**) или кнопку **New/Создать**.

### 3.1. Имя, тип системы и ISO

Заполните первую страницу мастера:

| Поле | Значение |
|---|---|
| **Name** | `FlyArchOs` или `FlyArchOs 1.7 beta` |
| **ISO Image** | скачанный `flyarchos-1.7.0-beta-x86_64.iso` |
| **Type** | `Linux` |
| **Version** | `Arch Linux (64-bit)` |
| **Skip Unattended Installation** | **включить** |

Галочка **Skip Unattended Installation** важна: FlyArchOs должна ставиться
через собственный графический установщик Calamares, а не через автоматический
сценарий VirtualBox. При этом выбранный ISO всё равно будет подключён к
виртуальному DVD-приводу новой машины.

### 3.2. Виртуальное оборудование

На странице оборудования поставьте:

- **Base Memory:** `12288 MB` (12 ГБ);
- **Processors:** `4`;
- **Enable EFI / Use EFI:** включить.

Если у хоста всего 8 ГБ свободной памяти, ВМ можно дать 6–8 ГБ, но Hyprland и
Plasma будут работать заметно тяжелее. Не выделяйте виртуальной машине всю
память и все ядра хоста.

### 3.3. Виртуальный жёсткий диск

- Выберите **Create a Virtual Hard Disk Now**.
- Тип файла: **VDI (VirtualBox Disk Image)**.
- Хранение: **Dynamically allocated**.
- Размер: **40 ГБ или больше**.

Динамический VDI сначала занимает на хосте мало места и растёт по мере записи
данных, но установщик видит именно заданный максимальный размер — 40 ГБ.

Нажмите **Finish/Готово**. Пока не запускайте машину: сначала проверьте
несколько настроек ниже.

## 4. Настройки перед первым запуском

Выделите созданную ВМ и нажмите **Settings/Настройки**.

### 4.1. Система

**Settings → System → Motherboard:**

- **Enable EFI:** включено;
- **Enable Secure Boot:** выключено;
- порядок загрузки:
  1. **Optical**;
  2. **Hard Disk**;
- **Floppy** и **Network** можно отключить.

**Settings → System → Processor:**

- процессоров: `4`;
- **Enable PAE/NX:** обычно уже включено;
- вложенную виртуализацию для обычной установки включать не нужно.

> Не переключайте BIOS ↔ EFI после установки без необходимости. Загрузчик
> ставится под тот режим прошивки, в котором загрузился установщик.

### 4.2. Экран

**Settings → Display → Screen:**

- **Graphics Controller:** `VMSVGA`;
- **Video Memory:** `128 MB`;
- **Monitor Count:** `1`;
- **Enable 3D Acceleration:** включить для первого запуска.

Если Hyprland после ввода пароля сразу возвращает экран SDDM, 3D-ускорение,
наоборот, должно быть **включено**: без рабочего OpenGL сессия Hyprland в
VirtualBox не стартует. Отключение 3D — только отдельный эксперимент при
артефактах или чёрном экране в Plasma; после него для входа выбирайте Plasma,
а не Hyprland. Остальные параметры при такой проверке не меняйте.

### 4.3. Накопители и подключённый ISO

**Settings → Storage** должен показывать примерно такую картину:

- контроллер SATA → виртуальный жёсткий диск `.vdi`;
- оптический привод → `flyarchos-1.7.0-beta-x86_64.iso`.

Если вместо ISO написано **Empty**, подключите образ вручную по инструкции из
следующего раздела.

### 4.4. Сеть

**Settings → Network → Adapter 1:**

- **Enable Network Adapter:** включено;
- **Attached to:** `NAT`;
- **Cable Connected:** включено.

Это лучший вариант для установки и повседневной проверки. Другие режимы сети
подробно разобраны в разделе 9.

### 4.5. Аудио и USB

**Settings → Audio:**

- **Enable Audio:** включено;
- контроллер по умолчанию, обычно **Intel HD Audio**.

**Settings → USB:**

- **Enable USB Controller:** включено;
- предпочтительно **USB 3.0 (xHCI) Controller**.

## 5. Как подключить ISO вручную

Этот раздел нужен, если:

- при создании ВМ ISO не выбрали;
- VirtualBox пишет `No bootable medium found`;
- хотите снова загрузиться в live-систему после установки;
- оптический привод показывает **Empty**.

### 5.1. Подключение при выключенной ВМ — основной способ

1. Полностью выключите виртуальную машину.
2. Откройте **Settings → Storage**.
3. В дереве устройств выберите оптический привод со статусом **Empty**.
   Если привода нет, выберите SATA-контроллер и нажмите значок добавления
   оптического привода.
4. Справа в разделе **Attributes** нажмите значок диска рядом с полем привода.
5. Выберите **Choose/Create a Virtual Optical Disk…**.
6. Нажмите **Add**, найдите файл `flyarchos-1.7.0-beta-x86_64.iso` и откройте его.
7. Выделите ISO в списке и нажмите **Choose**.
8. Убедитесь, что теперь в Storage вместо `Empty` указан ISO.
9. В **Settings → System → Motherboard** поставьте **Optical** первым в
   порядке загрузки.
10. Нажмите **OK** и запустите ВМ.

### 5.2. Подключение при запущенной ВМ

Подключить образ можно и на ходу:

**Devices → Optical Drives → Choose/Create a Virtual Optical Disk…**

Но уже загруженная система от этого не перезапустится с ISO. Для загрузки с
образа после подключения нужно перезагрузить ВМ и проверить порядок загрузки.

### 5.3. Чего не нужно делать

- Не подключайте к VirtualBox файл `.zip` — сначала распакуйте его.
- Не подключайте отдельную часть `.part00` — сначала склейте все части в ISO.
- Не открывайте ISO как обычный архив и не извлекайте его содержимое в папку.
- Не перемещайте и не переименовывайте ISO, пока он подключён к ВМ: VirtualBox
  хранит путь к файлу.

## 6. Первый запуск live-системы

Нажмите **Start/Запустить**.

1. Появится меню загрузки FlyArchOs — выберите обычный пункт загрузки.
2. Дождитесь рабочего стола. Live-сессия должна автоматически войти в
   Hyprland.
3. Если появился экран входа SDDM, используйте:
   - пользователь: `fly`;
   - пароль: `flyarchos`.

Полезные клавиши:

| Клавиши | Действие |
|---|---|
| `Super+Enter` | терминал Kitty |
| `Super+D` | меню приложений Wofi |
| `Super+B` | Firefox |
| `Super+E` | файловый менеджер |
| `Super+L` | блокировка экрана |
| `Host+F` | полный экран VirtualBox |
| `Host+C` | масштабируемый режим VirtualBox |

**Host** — специальная клавиша VirtualBox. На Windows и Linux по умолчанию это
правый `Ctrl`, на macOS обычно левый `Command`. Текущая клавиша Host показана в
правом нижнем углу окна ВМ. Однократное нажатие Host освобождает захваченную
клавиатуру.

Чтобы VirtualBox не перехватывала системные сочетания хоста, кликните внутрь
окна виртуальной машины. Для `Super` удобнее работать в полноэкранном режиме.

## 7. Установка FlyArchOs на виртуальный диск

В live-сессии:

1. Нажмите `Super+D`.
2. Введите `Install`.
3. Запустите **Install FlyArchOs**.

Если ярлык не находится, откройте терминал (`Super+Enter`) и выполните:

```bash
flyarchos-install
```

Для первой проверки рекомендуется базовый сценарий:

| Шаг установщика | Что выбрать |
|---|---|
| Язык | Русский |
| Разметка | **Стереть диск** |
| Диск | виртуальный диск на 40 ГБ |
| Файловая система | **btrfs** |
| Swap | **swap-файл** |
| Шифрование | для первого раза выключить |
| Окружение | **Hyprland + KDE Plasma** |
| Загрузчик | **GRUB** |
| Пользователь | создать своего пользователя |

Интернет установщику не нужен: пакеты уже лежат внутри ISO. Не выключайте ВМ
до завершения установки.

> «Стереть диск» относится к виртуальному `.vdi`, а не к физическому диску
> хоста. Но на странице сводки всё равно проверяйте, что выбран правильный
> виртуальный диск.

Подробное описание всех шагов и повторных сценариев проверки — в
[VIRTUALBOX-TEST.md](VIRTUALBOX-TEST.md) и [INSTALL.md](INSTALL.md).

## 8. Отключите ISO после установки

Это обязательный шаг. Если ISO оставить подключённым и первым в порядке
загрузки, после перезагрузки снова откроется live-система, а не установленная
FlyArchOs.

### Способ через меню запущенной ВМ

1. Дождитесь завершения установки.
2. В окне VirtualBox откройте **Devices → Optical Drives**.
3. Выберите **Remove disk from virtual drive**.
4. Перезагрузите ВМ из установщика или гостевой системы.

### Способ при выключенной ВМ

1. Полностью выключите ВМ.
2. Откройте **Settings → Storage**.
3. Выберите оптический привод с FlyArchOs ISO.
4. Нажмите значок диска и выберите удаление образа из привода, либо удалите
   сам оптический привод.
5. В **Settings → System → Motherboard** можно поставить **Hard Disk** первым.
6. Запустите ВМ.

После этого должен появиться GRUB/systemd-boot установленной системы, затем
экран входа SDDM. Входите уже под пользователем, которого создали в
установщике, а не под live-пользователем `fly`.

## 9. Подключение сети и интернета

NetworkManager в FlyArchOs включён. При стандартном режиме **NAT** интернет в
госте должен появиться автоматически после загрузки, отдельная настройка внутри
FlyArchOs не требуется.

### 9.1. Какой режим сети выбрать

| Режим VirtualBox | Интернет у гостя | Хост видит гостя | Другие ВМ видят гостя | Когда использовать |
|---|---:|---:|---:|---|
| **NAT** | да | только через проброс портов | нет | обычный запуск и установка |
| **NAT Network** | да | через проброс портов | да, внутри одной NAT-сети | несколько связанных ВМ |
| **Bridged Adapter** | да | да, по IP в локальной сети | да | гость как отдельное устройство в LAN |
| **Host-only Adapter** | нет по умолчанию | да | да | связь только с хостом и другими ВМ |
| **Internal Network** | нет | нет | да | изолированная сеть между ВМ |
| **Not Attached** | нет | нет | нет | полностью отключить сеть |

Для FlyArchOs по умолчанию оставляйте **NAT**.

Если список сетей для **NAT Network** или **Host-only Adapter** пуст, сеть
сначала создаётся в **Network Manager** главного окна VirtualBox, а уже потом
выбирается в настройках адаптера ВМ.

### 9.2. Проверка сети внутри FlyArchOs

Откройте терминал и выполните:

```bash
nmcli device status
ip -brief address
ping -c 1 1.1.1.1
getent hosts archlinux.org
curl -I https://archlinux.org
```

Ожидаемо при NAT:

- сетевой интерфейс имеет IPv4-адрес, обычно `10.0.2.15`;
- DNS превращает `archlinux.org` в IP-адрес;
- `curl` возвращает HTTP-заголовки.

Если адреса нет:

1. В **Settings → Network** проверьте **Enable Network Adapter** и **Cable Connected**.
2. В госте выполните `systemctl status NetworkManager`.
3. Откройте `nmtui` и активируйте проводное подключение.
4. Если меняли режим сети при работающей ВМ, перезагрузите гостя.

### 9.3. Bridged: гость как обычное устройство локальной сети

Если нужно обращаться к FlyArchOs с телефона или другого компьютера в домашней
сети:

1. Выключите ВМ.
2. **Settings → Network → Adapter 1 → Attached to: Bridged Adapter**.
3. В поле **Name** выберите физический адаптер хоста, через который хост ходит
   в интернет.
4. Запустите гостя и узнайте его адрес:

```bash
ip -brief address
```

Гость получит адрес от домашнего роутера. Учитывайте, что в bridged-режиме ВМ
видна другим устройствам локальной сети, поэтому не открывайте лишние сервисы.

Если роутер, публичный Wi-Fi или корпоративная сеть не выдаёт bridged-гостю
адрес, не чините это переустановкой: для VirtualBox это известное ограничение
конкретной сети. Вернитесь к NAT, а для прямого доступа с хоста добавьте
второй Host-only-адаптер по следующему пункту или проброс порта по разделу 10.

### 9.4. Host-only + NAT одновременно

Если одновременно нужны интернет и прямой доступ с хоста без проброса портов,
можно включить два адаптера:

- **Adapter 1:** NAT — интернет;
- **Adapter 2:** Host-only Adapter — прямой адрес между хостом и гостем.

Это удобно для SSH и тестовых серверов. Для обычной установки второй адаптер
не нужен.

## 10. Подключение к виртуальной машине по SSH

SSH удобен, чтобы копировать команды и файлы между хостом и установленной
FlyArchOs. Пакет `openssh` уже входит в образ, но служба `sshd` по умолчанию
не включена.

### 10.1. Включите SSH в установленной системе

В госте выполните:

```bash
sudo systemctl enable --now sshd.service
systemctl status sshd.service
ip -brief address
```

Если включён UFW:

```bash
sudo ufw allow OpenSSH
sudo ufw status
```

### 10.2. Вариант A: NAT + проброс порта

1. Откройте **Settings → Network → Adapter 1**.
2. Убедитесь, что выбран NAT.
3. Нажмите **Advanced → Port Forwarding**.
4. Добавьте правило:

| Поле | Значение |
|---|---|
| Name | `SSH` |
| Protocol | `TCP` |
| Host IP | `127.0.0.1` |
| Host Port | `2222` |
| Guest IP | можно оставить пустым |
| Guest Port | `22` |

Теперь на хосте подключайтесь так:

```bash
ssh -p 2222 ВАШ_ПОЛЬЗОВАТЕЛЬ@127.0.0.1
```

Привязка Host IP к `127.0.0.1` означает, что проброс доступен только с самого
хоста, а не из всей локальной сети.

Копирование файла с хоста в гостя:

```bash
scp -P 2222 ./file.txt ВАШ_ПОЛЬЗОВАТЕЛЬ@127.0.0.1:~/
```

### 10.3. Вариант B: Bridged или Host-only

Если у гостя есть прямой IP в сети хоста, проброс не нужен:

```bash
ssh ВАШ_ПОЛЬЗОВАТЕЛЬ@IP_ГОСТЯ
```

IP смотрите в госте командой `ip -brief address`.

## 11. Guest Additions: интеграция с хостом

Guest Additions добавляют удобную интеграцию: общие папки, общий буфер
обмена, drag-and-drop, синхронизацию времени и лучшую работу с размером окна.

> В сборках после Mini №58/Full №57 пакет `virtualbox-guest-utils` уже входит
> в FlyArchOs, а `vboxservice.service` включён. На №57/№58 выполните установку
> ниже в уже установленной системе; в live-сессии изменения исчезнут после
> перезагрузки.

Для FlyArchOs, как и для Arch Linux, предпочтительнее пакет из репозиториев
Arch, а не ручная установка с ISO Oracle. Не смешивайте оба способа: если
поставлен пакет Arch ниже, не запускайте дополнительно установщик через
**Devices → Insert Guest Additions CD Image**.

В установленной FlyArchOs выполните (команда с `--needed` безопасна и там, где
пакет уже есть):

```bash
sudo pacman -Syu --needed virtualbox-guest-utils
sudo systemctl enable --now vboxservice.service
sudo usermod -aG vboxsf "$USER"
sudo reboot
```

После перезагрузки проверьте:

```bash
systemctl status vboxservice.service
lsmod | grep -E 'vboxguest|vboxsf'
id
```

В `id` должна быть группа `vboxsf`. Если её нет, полностью выйдите из сеанса и
войдите снова или ещё раз перезагрузитесь.

### Если общий буфер обмена не заработал в Hyprland

Пакет ставит XDG-автозапуск `VBoxClient-all`. Plasma обычно запускает его сама;
в сборках FlyArchOs после №58 Hyprland тоже запускает его при обнаружении
VirtualBox. Если клиент не запущен, проверьте:

```bash
pgrep -a VBoxClient
```

Для разового запуска:

```bash
VBoxClient-all
```

Для постоянного запуска в старых сборках №57/№58 добавьте внутри
существующего обработчика `hyprland.start` в
`~/.config/hypr/hyprland.lua` строку:

```lua
hl.exec_cmd("VBoxClient-all")
```

Поддержка буфера обмена в Wayland зависит от версий VirtualBox, хоста и
гостевых утилит; версии VirtualBox на хосте и Guest Additions в госте лучше
держать близкими.

## 12. Общие папки, буфер обмена и drag-and-drop

### 12.1. Общая папка между хостом и гостем

1. Создайте на хосте отдельную папку, например `FlyArchOsShare`.
2. В VirtualBox откройте **Settings → Shared Folders**.
3. Нажмите значок добавления папки.
4. Заполните:
   - **Folder Path:** папка на хосте;
   - **Folder Name:** `share`;
   - **Auto-mount:** включить;
   - **Make Permanent:** включить;
   - **Read-only:** включить только если гостю нельзя изменять файлы.
5. Перезагрузите установленную FlyArchOs.

Обычно папка появляется как:

```text
/media/sf_share
```

Проверка:

```bash
ls -la /media/sf_share
```

Если автомонтирование не сработало, смонтируйте вручную:

```bash
sudo mkdir -p /mnt/share
sudo mount -t vboxsf -o uid="$UID",gid="$(id -g)" share /mnt/share
ls -la /mnt/share
```

Здесь `share` — именно Folder Name из настроек VirtualBox, а не путь на хосте.

Не используйте общую папку как домашний каталог, корень Git-репозитория для
сборки ISO или место с важными правами/симлинками: семантика `vboxsf`
отличается от обычной Linux-файловой системы.

### 12.2. Общий буфер обмена

**Settings → General → Advanced:**

- **Shared Clipboard:** `Bidirectional` — в обе стороны;
- или `Host to Guest` — безопаснее, если нужно только вставлять команды с хоста.

Эту настройку также можно менять на лету через
**Devices → Shared Clipboard**.

### 12.3. Drag-and-drop

**Settings → General → Advanced → Drag and Drop:**

- `Bidirectional` — перетаскивание файлов в обе стороны;
- `Host to Guest` — только с хоста в гостя.

Для буфера обмена и drag-and-drop нужны работающие Guest Additions. Если
функция не нужна постоянно, безопаснее держать её выключенной.

## 13. Подключение USB-устройства

VirtualBox может передать физическое USB-устройство напрямую гостю. Пока
устройство захвачено ВМ, хосту оно недоступно.

1. В **Settings → USB** выберите **USB 3.0 (xHCI)**.
2. Запустите ВМ.
3. Подключите устройство к компьютеру.
4. В окне ВМ откройте **Devices → USB** и выберите устройство.
5. В FlyArchOs проверьте:

```bash
lsusb
lsblk -f
```

Для USB-накопителя сначала безопасно извлеките его на хосте, если он уже
смонтирован. Перед отключением от ВМ размонтируйте накопитель внутри
FlyArchOs.

Если список USB пуст на Linux-хосте, пользователь хоста обычно должен входить
в группу `vboxusers`, после чего нужен выход из сеанса и повторный вход.

Не передавайте в гостя системный диск хоста и устройства, которые прямо сейчас
нужны хостовой ОС.

## 14. Разрешение экрана и полноэкранный режим

- Полный экран: **View → Full-screen Mode** или `Host+F`.
- Автоподстройка размера: **View → Auto-resize Guest Display**.
- В Plasma разрешение также меняется в **System Settings → Display**.
- В Hyprland список выходов можно посмотреть командой:

```bash
hyprctl monitors
```

Если картинка маленькая, сначала растяните окно ВМ или включите полный экран.
Если разрешение не меняется, проверьте, что видеоконтроллер — **VMSVGA**,
видеопамяти 128 МБ, а в установленной системе работает `vboxservice.service`.

## 15. Снапшоты и безопасное выключение

Снапшот позволяет вернуться к предыдущему состоянию ВМ. Удобно сделать
снапшоты:

1. после чистой установки и первого входа;
2. перед крупным обновлением;
3. перед экспериментами с разделами, загрузчиком и драйверами.

Создание: **Machine → Take Snapshot**. Восстановление: выберите ВМ →
**Snapshots** → нужный снапшот → **Restore**.

Снапшот — не полноценная резервная копия: он зависит от базового `.vdi`.
Для переноса ВМ на другой компьютер используйте **File → Export Appliance**.

Выключайте FlyArchOs обычным способом из гостевой системы. Если гость завис,
сначала попробуйте **Machine → ACPI Shutdown**. **Power Off** используйте
только в крайнем случае: это аналог выдергивания кабеля питания.

## 16. Диагностика проблем

### `No bootable medium found`

- ISO не подключён или в приводе стоит ZIP/`.part00` вместо готового `.iso`;
- в порядке загрузки первым стоит пустой жёсткий диск;
- включён Secure Boot;
- ISO повреждён — сверьте SHA-256.

Что сделать: выключить ВМ, подключить ISO по разделу 5, поставить Optical
первым, EFI включить, Secure Boot отключить.

### После установки снова загружается live-система

ISO всё ещё подключён и стоит раньше жёсткого диска. Отключите образ по
разделу 8 или поставьте Hard Disk первым.

### Чёрный экран после загрузки

1. Подождите 1–2 минуты при первом запуске.
2. Полностью выключите ВМ.
3. В **Display** проверьте VMSVGA, 128 МБ и **включённое 3D Acceleration** —
   это обязательный режим для Hyprland.
4. Запустите снова и попробуйте Hyprland.
5. Если именно с 3D видны артефакты или чёрный экран, отдельным экспериментом
   отключите 3D и на экране SDDM выберите **Plasma**. Hyprland без 3D может
   сразу возвращаться на экран входа — это ожидаемо.
6. Обновите VirtualBox на хосте, если оба варианта дают чёрный экран.

### Медленно: мышь, окна и анимации отстают

Виртуальная VMSVGA заметно медленнее обычной видеокарты, поэтому сначала
уменьшайте работу композитора, а не переустанавливайте систему:

1. Оставьте один виртуальный монитор, VMSVGA, 128 МБ видеопамяти и включённое
   3D. Для ВМ выделите 4 CPU и лучше 12 ГБ RAM, если хост позволяет.
2. Уменьшите окно/разрешение гостя до 1600×900 или 1280×720 и используйте
   масштаб 100%. Полный экран на 4K для VMSVGA может быть тяжёлым даже на
   быстром хосте.
3. В сборках после №58 облегчённый режим в ВМ включается автоматически.
   Проверка и ручное управление:

   ```bash
   flyarchos-performance status
   flyarchos-performance auto   # автоматически в ВМ
   flyarchos-performance on     # всегда лёгкая графика
   flyarchos-performance off    # полные эффекты
   ```

   В Hyprland его также переключает `Super+F1`. Режим отключает blur, тени и
   анимации в Hyprland, а в Plasma — blur/Magic Lamp и ставит мгновенные
   анимации. Если уже запущенная Plasma не применила эффект сразу, завершите
   сеанс и войдите снова.
4. На уже выпущенных №57/№58 автоматики ещё нет. В текущей сессии Hyprland
   эффекты можно временно выключить командой из терминала:

   ```bash
   hyprctl eval 'hl.config({animations={enabled=false},decoration={rounding=0,inactive_opacity=1,blur={enabled=false},shadow={enabled=false}},render={new_render_scheduling=true},misc={render_unfocused_fps=5}})'
   ```

   Вернуть конфиг: `hyprctl reload`. В Plasma на этих сборках поставьте
   **System Settings → Workspace Behavior → Animation speed → Instant** и
   отключите **Desktop Effects → Blur** и **Magic Lamp**.
5. Если медленно только первые 1–2 минуты, дождитесь окончания автозапуска:
   live-система одновременно поднимает панель, сеть, уведомления и помощника
   первого запуска.

### VirtualBox сообщает, что VT-x/AMD-V недоступна

- включите виртуализацию в BIOS/UEFI хоста;
- закройте другие гипервизоры, которые могут держать виртуализацию;
- на Windows проверьте конфликты с Hyper-V и Memory Integrity, если проблема
  сохраняется.

### Не открывается Calamares

Сначала убедитесь, что используете mini №58, full №57 или более новую
исправленную сборку, а не один из отозванных образов №49–№55. Mini №56 тоже
содержит Calamares по CI-проверкам, но для новой загрузки заменён №58.
В live-терминале выполните:

```bash
which calamares
pacman -Q calamares
ls /usr/lib/calamares/modules/packagechooser/
flyarchos-install
```

Если на Full №57/Mini №58 появляется
`explicitly configured application data directory is missing qml/`, это
известный баг `flyarchos-install`: он запускает Calamares с тестовым флагом
`-c /etc/calamares`, из-за чего пакетный `/usr/share/calamares/qml` не
рассматривается. Запустите установщик напрямую без `-c`, явно выбрав
native Wayland и программный GL для ВМ:

```bash
sudo --preserve-env=WAYLAND_DISPLAY,XDG_RUNTIME_DIR env QT_QPA_PLATFORM=wayland LIBGL_ALWAYS_SOFTWARE=1 calamares
```

`QT_QPA_PLATFORM=wayland` здесь обязательна: sudo не сохраняет
`XDG_SESSION_TYPE`, и без явного указания root-Qt на этих сборках выбирает
`xcb`, после чего падает с `could not connect to display :1`.

В следующих сборках launcher исправлен и снова достаточно
`flyarchos-install`.

Лог запуска Calamares:

```bash
sudo tail -n 300 /root/.cache/calamares/session.log
```

### Нет интернета

- проверьте **Cable Connected** в Network;
- для первого запуска верните режим NAT;
- в госте:

```bash
systemctl status NetworkManager
nmcli device status
ip -brief address
```

### Не работает SSH

- в госте служба запущена: `systemctl status sshd.service`;
- при NAT правило проброса указывает на Guest Port `22`;
- Host Port `2222` не занят другой программой;
- UFW разрешает `OpenSSH`;
- при Bridged/Host-only используется текущий IP гостя, а не старый из другой
  сети.

### Общая папка есть, но пишет Permission denied

- пользователь должен быть в группе `vboxsf`;
- после `usermod -aG vboxsf "$USER"` нужна перезагрузка или новый вход;
- проверьте `id` и `ls -ld /media /media/sf_share`;
- как запасной вариант используйте ручной `mount -t vboxsf` с `uid=` и `gid=`
  из раздела 12.1.

### USB-устройство не видно

- в настройках включён USB 3.0 (xHCI);
- устройство не занято программой на хосте;
- USB-накопитель безопасно извлечён на хосте перед захватом;
- на Linux-хосте пользователь входит в `vboxusers`;
- попробуйте другой физический USB-порт и заново выберите устройство через
  **Devices → USB**.

### Установщик говорит, что мало места

FlyArchOs — «жирный» офлайн-образ, установщику нужен запас. Создайте
виртуальный диск минимум на 40 ГБ. Увеличение динамического VDI после создания
возможно, но для первой установки проще пересоздать ВМ с правильным размером.
